# 13 · Especificação de software (TE1 / RA1)

Especificar é descobrir **o que** o software deve fazer antes de construí-lo.

## Etapas (indicadores ID1.1 a ID1.4)
1. **Elicitar** necessidades e expectativas (entrevista, questionário, observação, brainstorming).
2. **Analisar** viabilidade, consistência e prioridade; transformar necessidades brutas em requisitos técnicos.
3. **Documentar** funcionalidades, restrições e meios de desenvolvimento.
4. **Validar** com colegas e verificar a conformidade técnica.

## Tipos de requisito
- **Funcionais**: o que o sistema faz (ex.: "o usuário cadastra uma tarefa").
- **Não funcionais**: como faz (desempenho, segurança, usabilidade).
- **Restrições**: limites do projeto (prazo, tecnologia, orçamento).

## Um bom requisito é
Claro, verificável, consistente, viável e rastreável.

## Metodologia da disciplina
PBL (aprendizagem baseada em problemas): cenário de negócio confuso e contraditório, para filtrar ruído e extrair o escopo. Avaliação por pares.

## Modelo para o jogo
O *Game Design Document* (GDD) é a especificação de um jogo: ideia, mecânicas, personagens, fases, arte e som.
